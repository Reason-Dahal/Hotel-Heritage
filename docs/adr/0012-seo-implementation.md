# 0012. SEO implementation approach

## Status
Accepted

## Context
Search ranking is the project's top priority. Pages already render complete
content on the server (ADR 0001, ADR 0011). What remained was telling search
engines and social platforms what each page is, which pages exist, and which
areas to stay out of, without adding third-party scripts or hand-maintained
files.

## Decision
- **Metadata** comes from one helper (`src/lib/seo.ts`) fed by Site Settings, so
  every page gets a title, description, canonical URL, Open Graph, and Twitter
  tags in the same shape. The root layout supplies the title pattern and the
  base URL taken from `NEXT_PUBLIC_SITE_URL`.
- **`sitemap.xml` and `robots.txt`** are generated by `src/app/sitemap.ts` and
  `src/app/robots.ts`. The sitemap lists the three public pages with a
  `lastModified` date taken from the newest relevant record, and is rebuilt at
  least hourly. `priority` and `changefreq` are omitted because Google ignores
  them. `robots.txt` disallows `/admin` and `/api/`; the admin pages also carry
  a `noindex` tag.
- **Structured data** is JSON-LD rendered on the server: `Hotel` on the
  homepage, an `ItemList` of `HotelRoom` on Rooms, and a `Menu` on the menu page.
  Values come from the same data the page shows, and the JSON is escaped so no
  admin-entered text can break out of the script tag.
- **Image descriptions** are admin-controlled: a description for the hero photo
  (Site Settings) and per-photo descriptions in the gallery. Cards use the room
  or dish name.

## Alternatives Considered
- **An SEO plugin or third-party package**: adds a dependency for something the
  framework's metadata API already does.
- **Hand-written `sitemap.xml` and `robots.txt` in `public/`**: they would go
  stale as soon as content changes or the domain changes.
- **Client-side injected structured data**: crawlers may not run it reliably.

## Consequences
- Positive: no extra dependencies, one source of truth for site-wide details,
  and every change the admin makes flows into metadata and structured data
  automatically.
- Negative: the address is a single line rather than separate fields, which is
  weaker for local search. Rich results are never guaranteed. The sitemap and
  the page metadata depend on `NEXT_PUBLIC_SITE_URL` being set correctly on the
  live site, so it is on the deployment checklist.
